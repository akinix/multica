## Real-time / WebSocket

**Architecture:** Hub-and-spoke WebSocket with optional Redis relay for multi-instance deployments.

**Server-side:**
- `server/internal/realtime/hub.go` (25K) — Connection hub, manages per-workspace WS rooms
- `server/internal/realtime/broadcaster.go` — Event broadcasting
- `server/internal/realtime/redis_relay.go` (18K) — Cross-instance event relay via Redis Streams
- `server/internal/realtime/sharded_stream_relay.go` (7.5K) — Sharded Redis streams for scalability
- `server/internal/realtime/relay_lifecycle.go` — Redis relay lifecycle management
- Protocol: `gorilla/websocket` v1.5.3
- Auth: JWT or PAT (Personal Access Token) validated on WS upgrade via `hub.go`
- Membership verification: `MembershipChecker` interface ensures user belongs to workspace

**Client-side:**
- `packages/core/api/ws-client.ts` (5.8K) — TypeScript WS client with auto-reconnect
- `packages/core/realtime/index.ts` — Realtime event subscription hooks

**Event flow:**
1. Backend mutation writes to DB
2. Event emitted to `realtime.Hub`
3. Hub broadcasts to all connected clients in the workspace room
4. If Redis relay enabled, event also published to Redis Stream
5. Other server instances consume from Redis and broadcast to their local clients
6. Client receives WS message, invalidates relevant TanStack Query cache keys

**WS event types:** Defined in `packages/core/types/events.ts`. Include issue changes, comment events, agent status, inbox updates, workspace changes.

**Connection endpoint:** `/ws` (configured via `NEXT_PUBLIC_WS_URL`)

## Authentication

**Primary auth: Google OAuth 2.0**
- Flow: Frontend redirects to Google → callback to `/auth/callback` → backend exchanges code → creates/links user → issues JWT
- JWT stored in HTTP-only cookie (`server/internal/auth/cookie.go`)
- JWT secret: `JWT_SECRET` env var (fallback: dev secret)
- Implementation: `server/internal/handler/auth.go` (22K)

**Secondary auth: Personal Access Tokens (PAT)**
- Used by CLI and daemon for programmatic access
- PAT stored hashed in DB, resolved via `server/internal/auth/cloud_pat.go` (18.2K)
- Validated on every request via middleware (`server/internal/middleware/auth.go`)
- PAT cache: `server/internal/auth/pat_cache.go`

**Daemon auth:**
- Daemon-specific token flow (`server/internal/auth/daemon_token_cache.go`)
- WebSocket auth for daemon connections (`server/internal/middleware/daemon_auth.go`)

**Signup controls:**
- `ALLOW_SIGNUP` — enable/disable self-registration
- `ALLOWED_EMAILS` — whitelist specific emails
- `ALLOWED_EMAIL_DOMAINS` — whitelist email domains

**Multi-tenancy:** All queries filter by `workspace_id`. `X-Workspace-ID` header routes requests. Membership checks gate access (`server/internal/middleware/workspace.go`).

**Key files:**
- `server/internal/auth/jwt.go` — JWT secret management
- `server/internal/auth/cookie.go` — Cookie handling (7.1K)
- `server/internal/auth/cloud_pat.go` — PAT management (18.2K)
- `server/internal/auth/membership_cache.go` — Membership verification cache
- `server/internal/middleware/auth.go` — Auth middleware (9.6K)
- `server/internal/middleware/workspace.go` — Workspace context middleware (9.8K)
- `server/internal/middleware/daemon_auth.go` — Daemon-specific auth (8.9K)
- `server/internal/handler/auth.go` — Auth HTTP handlers (22K)
- `packages/core/auth/index.ts` — Frontend auth state
