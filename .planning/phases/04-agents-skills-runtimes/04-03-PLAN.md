Register routes:
- GET /api/skills -> ListSkills

- POST /api/skills/import -> ImportSkill (stub for Task 2)
- GET /api/skills/{id} -> GetSkill
- PUT /api/skills/{id} -> UpdateSkill
- DELETE /api/skills/{id} -> DeleteSkill

- PUT /api/skills/{id}/files -> UpsertSkillFile
- DELETE /api/skills/{id}/files/{fileId} -> DeleteSkillFile

Use app.MapGroup("/api/skills") for grouped routes.

ListSkills:
- Extract workspaceId from HttpContext.Items["WorkspaceId"]
- Query Skills where WorkspaceId matches, order by Name
- Include file_count via subquery or separate count query
- Return SkillResponse list

CreateSkill (per SKL-01):
- Validate name is not empty
- Create Skill entity with Id=NewGuid, WorkspaceId, Name, Description, Content, Config, CreatedBy from X-User-ID, CreatedAt/UpdatedAt=UtcNow
- Save and return SkillResponse

GetSkill:
- Find by Id and WorkspaceId, return 404 if not found
- Return SkillResponse with file_count

UpdateSkill:
- Find skill, validate exists
- Update only provided fields (name, description, content, config)
- Set UpdatedAt=UtcNow, save, return SkillResponse

DeleteSkill:
- Find skill, validate exists
- In transaction: delete skill and all associated SkillFiles and AgentSkills
- Return 204 NoContent

ListSkillFiles (per SKL-02):
- Find skill, validate exists
- Query SkillFiles where SkillId matches, order by Path
- Return SkillFileResponse list

UpsertSkillFile:
- Parse request: { path, content }
- Validate path is not empty
- Find existing SkillFile by (SkillId, Path)
- If exists: update Content and UpdatedAt
- If not: create new SkillFile with Id=NewGuid
- Save and return SkillFileResponse

DeleteSkillFile:
- Parse fileId from route
- Find SkillFile by Id and SkillId
- Delete and return 204

Helper: SkillToResponse(Skill, int fileCount) -> SkillResponse conversion.
Helper: SkillFileToResponse(SkillFile) -> SkillFileResponse conversion.

Register MapSkillEndpoints in Program.cs after MapAgentEndpoints.

Implement the ImportSkill endpoint handler (POST /api/skills/import) per SKL-03 and D-04.

ImportSkill implementation:
- Parse request: { url: string }
- Detect source using URL parsing (per Go's detectImportSource pattern):
  - "clawhub.ai" or "www.clawhub.ai" -> ClawHub source
  - "skills.sh" or "www.skills.sh" -> Skills.sh source
  - "github.com" or "www.github.com" -> GitHub source
  - URL without "/" or "." -> treat as ClawHub slug
  - Other -> return 400 "unsupported source"
- Normalize URL (add https:// if missing)

Fetch logic by source:

ClawHub:
- Fetch skill metadata from ClawHub API
- Parse response to extract name, description, content, config, files
- Use IHttpClientFactory for HTTP calls (per Don't Hand-Roll)

Skills.sh:
- Parse URL to extract owner/repo/skillName
- Fetch skill markdown from skills.sh API
- Parse frontmatter for name/description
- Fetch associated files

GitHub:
- Parse URL to extract owner/repo/path
- Use GitHub API (raw.githubusercontent.com or api.github.com) to fetch skill.md
- Parse frontmatter for name/description
- Fetch all .md files in the skill directory
- Skip binary files (per Pitfall 3): check extension blacklist (.png, .jpg, .gif, .svg, .ico, .woff, .woff2, .ttf, .eot, .mp3, .mp4, .avi, .mov, .zip, .tar, .gz, .pdf, .exe, .dll, .so, .dylib)
- Validate file paths (per Pitfall 5): reject absolute paths and paths starting with ".."

Create skill:
- In transaction: create Skill entity, create SkillFile entities for each file
- Per D-04: create new Skill record preserving all fields from source
- Set CreatedBy from X-User-ID, CreatedAt/UpdatedAt=UtcNow
- Save and return SkillResponse

Add IHttpClientFactory registration in Program.cs if not already present:
`builder.Services.AddHttpClient();`

Use SemaphoreSlim for concurrent file fetches (max 5 concurrent) matching Go's sync.WaitGroup pattern.
Set HTTP timeout to 30 seconds per source (per Assumption A4).
