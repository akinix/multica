Add update flow and delete endpoints to RuntimeEndpoints:

InitiateUpdate (per RT-03):
- Find runtime by runtimeId and workspaceId
- Inject IRuntimeUpdateStore
- Call store.InitiateUpdateAsync(runtimeId, payload, timeout)
- Return RuntimeUpdateResponse with update_id and status="pending"

GetUpdate:
- Find runtime by runtimeId and workspaceId
- Inject IRuntimeUpdateStore
- Call store.GetResultAsync(runtimeId, updateId)
- Return RuntimeUpdateResponse with current status and response data

DeleteAgentRuntime (per RT-07):
- Find runtime by runtimeId and workspaceId
- Check for active agents bound to this runtime (query Agents where RuntimeId matches and ArchivedAt is null)
- If active agents exist: return 409 with { error: "runtime_has_active_agents", active_agent_count: N }
- If no active agents: delete runtime in transaction
- Also delete related AgentTaskQueue entries for this runtime
- Return 204 NoContent

ArchiveAgentsAndDeleteRuntime (per RT-07, Pitfall 7):
- Find runtime by runtimeId and workspaceId
- In transaction with FOR UPDATE lock on runtime row:
  1. Query all active agents bound to this runtime
  2. Archive each agent (set ArchivedAt, ArchivedBy)
  3. Cancel all active tasks for these agents (set Status="cancelled", CompletedAt=UtcNow)
  4. Delete the runtime
- Compare expected vs actual active agent set; return 409 with runtime_delete_plan_changed if mismatch
- Return 204 NoContent on success

Use `db.Database.BeginTransactionAsync()` for cascade operations.
Use `SELECT ... FOR UPDATE` equivalent via EF Core: `await db.AgentRuntimes.Where(r => r.Id == runtimeId).AsNoTracking().FirstOrDefaultAsync()` then re-fetch with tracking inside transaction.
