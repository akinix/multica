Create RuntimeLivenessEndpoints.cs as static class with MapRuntimeLivenessEndpoints(this WebApplication app) in namespace Multica.Api.Handlers.

Register routes (per D-05, D-06, D-07, D-08):
- POST /api/runtimes/{runtimeId}/heartbeat -> Heartbeat
- GET /api/runtimes/{runtimeId}/liveness -> GetLiveness

Heartbeat:
- Find runtime by runtimeId and workspaceId (from HttpContext.Items["WorkspaceId"])
- Inject IRuntimeLivenessStore
- Call store.TouchAsync(runtimeId.ToString(), TimeSpan.FromSeconds(60)) per D-08
- Update runtime.LastSeenAt = UtcNow in DB
- Return 200 OK with { status: "ok" }

GetLiveness:
- Find runtime by runtimeId and workspaceId
- Inject IRuntimeLivenessStore
- Call store.IsAliveBatchAsync(new[] { runtimeId.ToString() })
- If store not available (Available=false), fall back to DB: check runtime.LastSeenAt within last 60 seconds (per Pitfall 4)
- Return RuntimeLivenessResponse with alive status and last_heartbeat timestamp

Register MapRuntimeLivenessEndpoints in Program.cs after MapRuntimeEndpoints.

The liveness endpoints are separate from RuntimeEndpoints because they are called by daemon processes (different auth context) and have different security requirements.
