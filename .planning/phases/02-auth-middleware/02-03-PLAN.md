</read_first>

<action>
Create `server/src/Multica.Api/Middleware/AuthMiddleware.cs`:
- Constructor: takes all auth services via DI
- Middleware flow (matching Go priority):
  1. Strip any client-supplied `X-Actor-Source` header
  2. Extract token: `Authorization: Bearer <token>` header → `multica_auth` cookie
  3. If from cookie: validate CSRF via `CsrfValidator.ValidateCsrf()`
  4. Dispatch by prefix:
     - `mat_` → TaskTokenValidator: set X-User-ID, X-Agent-ID, X-Task-ID, X-Workspace-ID, X-Actor-Source=task_token
     - `mcn_` → CloudPatVerifier: set X-User-ID (owner_id from Fleet)
     - `mul_` → PatCache → DB fallback: set X-User-ID
     - Default → JWT validation: set X-User-ID, X-User-Email
  5. Call `next()` on success
  6. Return 401 on failure, 403 on CSRF failure, 503 on cloud unavailable

Token extraction logic:
```csharp
private static (string token, bool fromCookie) ExtractToken(HttpContext context)
{
    var authHeader = context.Request.Headers.Authorization.ToString();
    if (authHeader.StartsWith("Bearer "))
        return (authHeader[7..], false);

    if (context.Request.Cookies.TryGetValue("multica_auth", out var cookie) && !string.IsNullOrEmpty(cookie))
        return (cookie, true);

    return ("", false);
}
```

Headers set on success:
- `X-User-ID`: user UUID (all paths)
- `X-User-Email`: email (JWT path only)
- `X-Agent-ID`: agent UUID (task token path only)
- `X-Task-ID`: task UUID (task token path only)
- `X-Workspace-ID`: workspace UUID (task token path only)
- `X-Actor-Source`: "task_token" (task token path only)
</action>

<acceptance_criteria>
- Token extraction matches Go: Authorization header priority over cookie
- CSRF validation on cookie-based auth for non-safe methods
- mat_ path sets all 4 headers including X-Actor-Source
- mcn_ path returns 503 when Fleet unreachable, 401 when invalid
- mul_ path uses cache, falls back to DB on miss
- JWT path extracts sub and email claims
- X-Actor-Source always stripped before auth branches
- Unit tests for each token path
</acceptance_criteria>

<action>
Create `server/src/Multica.Api/Middleware/WorkspaceMiddleware.cs`:

**Workspace resolution** (matching Go priority):
1. Task token binding (X-Actor-Source == "task_token") → use X-Workspace-ID directly
2. X-Workspace-Slug header → EF Core query `GetWorkspaceBySlug()`
3. ?workspace_slug query → EF Core query
4. X-Workspace-ID header → use directly
5. ?workspace_id query → use directly

**Membership validation:**
- Query `Members` table: `WHERE UserId == userId AND WorkspaceId == workspaceId`
- If not found: 404 "workspace not found"
- If roles specified: check `member.Role` is in allowed roles

**Context injection:**
- `HttpContext.Items["WorkspaceId"]` = workspace UUID
- `HttpContext.Items["Member"]` = Member entity

**Extension methods:**
- `app.UseRequireWorkspaceMember()` — validates membership
- `app.UseRequireWorkspaceRole("admin", "owner")` — validates role

**Task token binding check:**
- If X-Actor-Source == "task_token", verify resolved workspace matches X-Workspace-ID
- Mismatch → 403 "task token is bound to a different workspace"
</action>

<acceptance_criteria>

<action>
Create `server/src/Multica.Api/Middleware/RateLimitMiddleware.cs`:
- Constructor: `RateLimitMiddleware(RequestDelegate next, IDatabase redis, IConfiguration config)`
- Config keys:
  - `RateLimit:Limit` (default 100)
  - `RateLimit:WindowSeconds` (default 60)
  - `RateLimit:TrustedProxies` (comma-separated CIDRs, default empty)
- Redis Lua script (same as Go):
  ```lua
  local count = redis.call('INCR', KEYS[1])
  if count == 1 then
      redis.call('EXPIRE', KEYS[1], ARGV[1])
  end
  return count
  ```
- Key format: `mul:ratelimit:{sanitized_path}:{ip}`
- IP extraction: same trusted-proxy logic as Go
  - If RemoteAddr is in trusted CIDRs → read X-Forwarded-For rightmost non-trusted
  - Otherwise → use RemoteAddr
- On limit exceeded: 429 + `Retry-After` header + `{"error": "too many requests"}`
- Fail-open: Redis errors → allow request

Extension method: `app.UseRateLimit()` or per-route rate limiting.
</action>

<acceptance_criteria>
- Redis Lua script is identical to Go
- Key format matches Go: `mul:ratelimit:{path}:{ip}`
- IP extraction with trusted proxy support matches Go
- 429 response includes Retry-After header
- Fail-open on Redis errors
- Integration test: first N requests pass, N+1 gets 429
</acceptance_criteria>
