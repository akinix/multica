## Plan 01: Token Generation, Validation & Caching

**Objective:** Implement all token types (JWT, PAT, daemon, task, cloud PAT) with Redis caching — the foundation for the auth middleware.

### Task 1.1: Token Hasher & JWT Service

<read_first>
- server/internal/auth/jwt.go (Go reference: token generation, HashToken)
- server/src/Multica.Infrastructure/DependencyInjection.cs (DI registration pattern)
- server/src/Multica.Api/appsettings.json (configuration pattern)
</read_first>

<action>
Create `server/src/Multica.Core/Auth/TokenHasher.cs`:
- Static class with `HashToken(string token) → string` method
- Uses `SHA256.HashData(Encoding.UTF8.GetBytes(token))` → `Convert.ToHexString().ToLowerInvariant()`
- Must match Go's `hex.EncodeToString(sha256.Sum256([]byte(token)))` exactly

Create `server/src/Multica.Core/Auth/JwtTokenService.cs`:
- `GenerateToken(Guid userId, string email) → string` — creates JWT with `sub` and `email` claims
- `ValidateToken(string token) → ClaimsPrincipal?` — validates HMAC-SHA256 JWT
- Uses `System.IdentityModel.Tokens.Jwt` (`JwtSecurityTokenHandler`)
- Signing key from `IConfiguration["Jwt:Secret"]` with fallback to `"multica-dev-secret-change-in-production"`
- Token expiry from `IConfiguration["Auth:TokenTTL"]` with fallback to 30 days
- Claims: `sub` = userId.ToString(), `email` = email

Add to `appsettings.json`:
```json
{
  "Jwt": {
    "Secret": "multica-dev-secret-change-in-production"
  },
  "Auth": {
    "TokenTTL": "30.00:00:00",
    "CacheTTL": "00:10:00",
    "MembershipCacheTTL": "00:05:00",
    "CloudPatCacheTTL": "00:01:00"
  }
}
```
</action>

<acceptance_criteria>
- `TokenHasher.HashToken("test")` returns the same hex string as Go's `auth.HashToken("test")`
- `JwtTokenService.GenerateToken()` returns a valid JWT with correct claims
- `JwtTokenService.ValidateToken()` returns ClaimsPrincipal for valid tokens, null for expired/invalid
- Unit tests pass for both token hashing and JWT generation/validation
</acceptance_criteria>

### Task 1.2: PAT Token Cache (mul_)

<read_first>
- server/internal/auth/pat_cache.go (Go reference: Redis key scheme, TTL logic)
- server/src/Multica.Infrastructure/Redis/RedisConnectionProvider.cs (Redis access pattern)
</read_first>

<action>
Create `server/src/Multica.Core/Auth/PatCache.cs`:
- Constructor: `PatCache(IDatabase redis)`
- Key prefix: `"mul:auth:pat:"`
- `GetAsync(string hash) → Task<string?>` — returns cached userId or null
- `SetAsync(string hash, string userId, TimeSpan? ttl)` — stores with TTL
- `InvalidateAsync(string hash)` — deletes key
- `TTLForExpiry(DateTime now, DateTime? expiresAt) → TimeSpan` — clamps to min(cacheTTL, remaining lifetime)
- Default TTL from config: 10 minutes
- Nil-safe: all methods no-op if redis is null
- All Redis errors logged and swallowed (fail-open)
</action>

<acceptance_criteria>
- Redis key format matches Go: `mul:auth:pat:{hash}`
- TTL clamping works: token expiring in 5 min gets 5 min TTL, not 10 min
- Cache miss returns null, not exception
- Integration test: Set → Get → Invalidate → Get returns null
</acceptance_criteria>

### Task 1.5: Cloud PAT Verifier (mcn_)

<read_first>
- server/internal/auth/cloud_pat.go (Go reference: Fleet API contract, caching, error types)
- server/src/Multica.Core/Auth/PatCache.cs (Redis caching pattern)
</read_first>

<action>
Create `server/src/Multica.Core/Auth/CloudPatIdentity.cs`:
- Record with: `OwnerGuid` (Guid), `InstanceId` (string), `InstanceRecordId` (string)

Create `server/src/Multica.Core/Auth/CloudPatVerifier.cs`:
- Constructor: `CloudPatVerifier(HttpClient httpClient, IDatabase? redis, string fleetBaseUrl)`
- `VerifyAsync(string token, Func<string, Task<bool>>? ownerLookup) → Task<CloudPatIdentity>`
- Flow: Redis cache → Fleet POST /api/v1/pat/verify → owner existence check → cache result
- Cache TTL: 60 seconds (configurable)
- Error types: `CloudPatInvalidException`, `CloudPatUnavailableException`
- Fleet request: `{"token": "mcn_..."}` 
- Fleet response: `{"valid": true, "owner_id": "...", "instance_id": "...", "instance_record_id": "..."}`
- Cache key: `mul:auth:mcn:{hash}`
- Do NOT cache negative results (valid=false or owner_unknown)
- HttpClient timeout: 5 seconds
</action>

<acceptance_criteria>
- Redis cache key matches Go: `mul:auth:mcn:{hash}`
- Fleet API contract matches Go: same request/response JSON shape
- Cache hit skips Fleet call
- Negative results (invalid token, unknown owner) are NOT cached
- 503 returned when Fleet is unreachable (not 401)
- Unit test with mock HttpClient verifying request/response flow
</acceptance_criteria>
