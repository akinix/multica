   - Query issues where ParentIssueId == parent.Id
   - Return { "issues": [...] }

2. **ListChildrenByParents Endpoint**: `GET /api/issues/children?parent_ids={uuid1},{uuid2}`
   - Parse comma-separated parent_ids
   - Validate max 200 parent IDs
   - Query issues where ParentIssueId is in the list
   - Filter by workspace
   - Return { "issues": [...] }

3. **ChildIssueProgress Endpoint**: `GET /api/issues/child-progress`
   - Get workspace from X-Workspace-ID header
   - Query: GROUP BY parent_issue_id, COUNT(*) as total, COUNT(*) WHERE status='done' as done
   - Only include issues that have a parent (ParentIssueId IS NOT NULL)
   - Return { "progress": [{ "parent_issue_id": "uuid", "total": 5, "done": 3 }] }

4. **Cycle Detection** (add to UpdateIssue logic):
   - When updating parent_issue_id, walk up from new parent
   - Max depth: 10
   - If current issue found in ancestor chain, return 400 "circular parent relationship detected"
   - Also validate parent exists in same workspace

5. **Inherit Project** (add to CreateIssue logic):
   - When parent_issue_id is set and project_id is not
   - Copy project_id from parent issue
