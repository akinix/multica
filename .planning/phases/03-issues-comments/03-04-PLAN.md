Add batch endpoints to IssueHandler.cs:

1. **Request DTOs**:
   - BatchUpdateIssuesRequest: { issue_ids: string[], updates: UpdateIssueRequest }
   - BatchDeleteIssuesRequest: { issue_ids: string[] }

2. **BatchUpdateIssues Endpoint**: `POST /api/issues/batch/update`

   Logic (per D-09, D-11, D-12):
   - Parse request body
   - Validate issue_ids is not empty
   - Validate issue_ids length <= 100 (per D-12)
   - Detect which fields in "updates" are explicitly set (including null)
   - Short-circuit if no mutation fields present → return {"updated": 0}
   - Begin database transaction (per D-09)
   - Loop through issue_ids:
     - Parse UUID, skip if invalid
     - Load issue in workspace, skip if not found
     - Apply updates (only explicitly set fields)
     - Validate assignee pair if changed
     - Save changes
     - Increment counter
   - Commit transaction
   - Return {"updated": count}

   Supported update fields (per D-11):
   - title, description, status, priority, position
   - assignee_type, assignee_id (null = unassign)
   - start_date, due_date (null = clear)
   - parent_issue_id (null = remove parent, validate no cycles)
   - project_id (null = remove project)

3. **BatchDeleteIssues Endpoint**: `POST /api/issues/batch/delete`

   Logic (per D-10):
   - Parse request body
   - Validate issue_ids is not empty
   - Validate issue_ids length <= 100
   - Loop through issue_ids:
     - Parse UUID, skip if invalid
     - Load issue in workspace, skip if not found
     - Delete issue
     - Increment counter
   - Return {"deleted": count}

   Note: Unlike batch update, batch delete does NOT use a transaction (per Go behavior - each delete is independent).
